# 시험지 OCR (ExamOCR) — 작업 규칙

전체 현황·다음 할 일은 저장소 맨 위 `작업현황.md`를 본다. 이 문서는 고칠 때 지킬 규칙만 적는다.

## 사용자와 보고
- 사용자(학원 선생님)는 코드를 직접 짜지 않는다. 실행 안내는 "어느 파일을 어디에 두고 무엇을 두 번 누르는지" 수준으로 쓴다.
- 보고는 한국어, TL;DR 먼저. 확인한 것과 추정한 것을 나눠 쓴다.
- main에는 사용자 허락 없이 합치지 않는다. 고친 것은 별도 브랜치로 올린다.

## 지킬 원칙
- 정확도가 떨어지는 속도 개선은 하지 않는다.
- 레이아웃 보정은 기존 샘플 결과를 한 글자라도 바꾸면 채택하지 않는다.
- 원문자(①~⑤, ⓐ~ⓚ)·손글씨·낙서는 제어하지 않는다. 나오는 대로 두고 사용법에 안내한다.
- 자신 없는 글자 뒤에는 `[?]`를 붙인다 (`--mark-low`).
- 표·박스는 칸 하나짜리 표로 감싸기만 한다. 칸 구조는 살리지 않고, 글자·읽는 순서는 바꾸지 않는다.
- 처음 보는 시험지 검증 기준: 빠진 줄 0, 읽는 순서가 맞는 쪽 95% 이상.
- 저사양판 판정 기준: 기본판 결과와 글자 일치율 99% 이상, 빠진 줄 0, 속도 쪽당 5분 이하.

## 고치는 곳
- 시험지 OCR은 이 폴더(`OCR/ExamOCR_build/`)만 고친다. 판별 파일 구성은 저장소 맨 위 `README.md`.
- `ocr_paddle.py` 하나를 기본판·저사양판·전자책 OCR(`EbookOCR/ebook_ocr.py`)이 함께 쓴다.
  고칠 때 `to_items`, `group_rows`, `build_ocr`, `default_options`, `load_image`의 모양을 바꾸면 전자책 쪽도 확인한다.
- `models/`, `models_onnx/`, `.venv*`, `dist/`, `installer*/`는 빌드 bat이 만든다. 저장소에 넣지 않는다.
- 시험지 PDF·이미지는 저장소(공개)에 올리지 않는다.

## 파일 형식 (고친 뒤 `file`로 확인)
| 파일 | 형식 |
|---|---|
| `.bat` | CRLF, 첫머리 `chcp 65001` |
| `.iss`, `사용법.txt` | UTF-8 BOM + CRLF |
| `.py`, `.spec`, `.md` | UTF-8 (BOM 없음), LF |

## 확인 방법
- 리눅스에서는 PaddleOCR 없이 시험할 수 있다: OpenCV·python-hwpx만 깔고 합성 이미지로 `find_boxes`·`box_of`를,
  `PageResult`를 직접 만들어 `write_hwpx`를 시험한다. Windows 빌드·설치본·한글 확인은 사용자가 한다.
- HWPX 글자 뽑기: `<hp:t>`의 글자 + 자식 `<hp:tab/>`은 탭 + 각 자식의 `tail`까지 이어 붙여야 기준 텍스트와 맞는다.
  표가 든 문단은 건너뛰고 표 안 문단을 읽는다.
- 일치율은 글자 단위 `difflib.SequenceMatcher`로 잰다.
