## 2. 본인 역할

- **문제 정의**: 학원에서 종이 시험지를 한글 문서로 다시 치는 시간을 줄이기, 전자책 내용을 NotebookLM 등 AI 지식 도구에 넣어 공부하기.
- **요구사항 문서화**: 기능 요청을 "요청서"로 써서 전달 (예: 전자책 교정 도구 요청서 v1 → v2 → v2.1 → v2.2 → v3). 지킬 것, 확인된 문제(위치 포함), 요청, 시험 시나리오와 기대 결과를 한 문서에 정리.
- **원칙 결정**: "정확도가 떨어지는 속도 개선은 하지 않는다", "레이아웃 보정은 기존 샘플 결과를 한 글자라도 바꾸면 채택하지 않는다", "자신 없는 글자 뒤에는 `[?]`" 등 (§5).
- **현장 검증**: 실제 시험지 3종, 실제 전자책 여러 권, 집 PC(그래픽카드)·노트북·AVX 없는 구형 PC에서 직접 설치·실행하고 결과 화면을 보고서로 돌려줌.
- **우선순위·범위 조정**: 기능을 넣는 것뿐 아니라 빼는 결정도 함 (예: 머리말·꼬리말 자동 삭제, 그림 판정으로 글자 버리기 → 사람이 직접 지우는 방식으로 전환, §4).

## 4. 문제 해결 사례 (실사용 보고 → 원인 → 조치)

| # | 사용자 보고 | 원인 (근거) | 조치 |
|---|---|---|---|
| 1 | 결과에 표가 0개로 나옴 | 다른 날 만든 설치 파일을 설치함 | 결과가 이상하면 설치된 실행 파일 날짜부터 확인하도록 명세에 기록 |
| 2 | 얇은 회색 테두리 박스를 못 잡음 | 선 판정 밝기 160이 너무 엄격 | 비침 판정과 같은 180으로 통일, 기존 결과 글자 차이 0 확인 |
| 3 | AI 교정이 응답 없이 멈춤 | 무료 키로 쓴 모델이 매우 느리고 혼잡(503) | 조각 받기(stream), 시간 제한, 출력 한도 자동, 다른 모델·서비스로 넘기는 자동 모드 |
| 4 | (요청서) AI 요약의 인용 검사에 **책에 인쇄된 쪽 번호**가 필요 | 도구 안 쪽 번호는 캡처 순번이라 표지·그림 쪽 때문에 인쇄 쪽 번호와 어긋남 | 캡처 번호는 그대로 두고, 챕터 시작·번호 교정 설정으로 **책 쪽 번호를 계산**해 표시·내보내기에만 사용 |
| 5 | 쪽 맨 위 번호 목록("1. …")이 사라짐 | 머리말·꼬리말 규칙(맨 위·아래 두 줄, 숫자로 시작하는 짧은 줄)이 번호 목록과 같은 모양 | 정규식으로 재현해 원인 확인 → 사용자 결정으로 자동 삭제 기능 제거, 회귀 시험 추가 |
| 6 | 색이 많은 표의 글자가 빠짐 | 그림 판정(채움 비율)이 색 표를 그림으로 보고 그 안 글자를 버림 | 글자는 모두 남기고 그림 영역은 편집기 점선 표시로만 사용. 예전 캐시는 그림 있던 쪽만 다시 인식 |
| 7 | 영역 지우기 뒤 `> 주:` 껍데기가 남음 | 각주 줄의 내용만 지우고 표시 기호는 남김 | 원인 분석·수정 방안 제시 (사용자 결정 대기) |

## 5. 품질 원칙과 검증

**원칙** (본인 결정, `OCR/ExamOCR_build/CLAUDE.md`·`SPEC.md` §2)
- 정확도가 떨어지는 속도 개선은 하지 않는다.
- 레이아웃 보정·새 기능은 기존 샘플 결과를 한 글자라도 바꾸면 채택하지 않는다.
- 글자는 항상 원본 이미지에서 읽고, 전처리 이미지는 판정에만 쓴다.
- 시험지 원본과 결과는 저장소에 올리지 않는다 (학교 저작물).
- 보고는 확인한 것과 추정한 것을 나눠 쓴다.

**시험지 OCR 기준 결과** (실제 시험지 3종)

| 비교 | 결과 |
|---|---|
| 표 기능 추가 전 ↔ 후 | 글자 차이 0 (297·322·401줄) |
| 저사양판 ↔ 일반판 | 2종 완전 동일, 1종 99.98% (손글씨 2곳) |
| 그래픽카드 ↔ CPU | 99.91~99.95% |
| 같은 입력 반복 | CPU·그래픽카드 각각 완전 동일 |
| 속도 | 일반판 쪽당 약 74초(노트북 CPU), 그래픽카드 시험지 4쪽 약 5초 |

**전자책 OCR 자동 시험** (리눅스, OCR 엔진 없이 실행 가능하게 설계)
- `tests/test_export.py` 9개: 장별 파일·머리 정보·쪽 표시·제외 챕터·Word 제목 단계·예전 파일 호환(골든 파일 비교)
- `tests/test_editor.py`: 브라우저 자동화(Playwright)로 목차 입력·챕터 설정·제목 일괄 정리·고른 글 제목으로 떼기까지 실제 화면 조작
- `tests/test_reocr.py`: 가짜 OCR 엔진으로 영역 다시 읽기의 좌표 되돌리기(여백·2배 확대)와 편집기 흐름
- `tests/test_ocr_headers.py`: 인식 캐시로 OCR 마무리 단계 실행, 맨 위·아래 줄과 작은 글자 보존
